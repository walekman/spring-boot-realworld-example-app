P0 — SECURITY (Fix before any other work)
=======================================================

P0-1 | Plaintext password stored on user update              [NEW — plan2 only]
  File:   src/main/java/io/spring/application/user/UserService.java:50
          src/main/java/io/spring/core/user/User.java:39
  Issue:  updateUser() passes raw UpdateUserParam.getPassword() to User.update()
          with no encoding. A user who changes their password via PUT /user gets
          a bcrypt-less plaintext string written to the DB.
  Fix:    In UserService.updateUser(), encode before delegating:
            if (!Util.isEmpty(updateUserParam.getPassword())) {
                encodedPassword = passwordEncoder.encode(updateUserParam.getPassword());
            }
          Pass encodedPassword (or null/empty) to user.update().
  Effort: XS

P0-2 | GraphQL endpoint fully unauthenticated               [NEW — plan2 only]
  File:   src/main/java/io/spring/api/security/WebSecurityConfig.java:56-57
  Issue:  .antMatchers("/graphql").permitAll() bypasses all REST auth rules.
          Mutations for creating articles, updating users, and following are
          accessible without a token.
  Fix:    Remove permitAll() for /graphql. Enforce authentication per-resolver
          by checking SecurityUtil.getCurrentUser() and throwing on empty, or
          apply a security expression on the /graphql path globally.
  Effort: S

P2 — DESIGN ANTI-PATTERNS
=======================================================

P2-1 | WebSecurityConfigurerAdapter is deprecated           [both plans]
  File:   src/main/java/io/spring/api/security/WebSecurityConfig.java:24
  Issue:  Deprecated in Spring Security 5.7, removed in Spring Security 6.
          Extending it will be a breaking change on the next major upgrade.
  Fix:    Migrate to SecurityFilterChain @Bean:
            @Bean
            public SecurityFilterChain filterChain(HttpSecurity http) throws Exception { ... }
          Drop the extends clause. Register JwtTokenFilter via
          http.addFilterBefore(...) inside the bean method.
  Effort: M

P2-2 | JwtTokenFilter uses field @Autowired on a non-component class  [both plans]
  File:   src/main/java/io/spring/api/security/JwtTokenFilter.java:18-22
  Issue:  @SuppressWarnings("SpringJavaAutowiringInspection") suppresses a
          real problem. Field injection on a manually-constructed object is
          fragile and breaks in tests without a running Spring context.
  Fix:    Add constructor: JwtTokenFilter(JwtService jwtService, UserRepository userRepository).
          In WebSecurityConfig.jwtTokenFilter(), pass both dependencies explicitly.
          Remove @Autowired fields and @SuppressWarnings.
  Effort: XS

P2-3 | UpdateUserConstraint/Validator defined inside UserService.java  [plan.txt M2 / plan2 #7]
  File:   src/main/java/io/spring/application/user/UserService.java:59-106
  Issue:  Package-private annotation and validator class co-located with the
          service. Inconsistent with DuplicatedEmailValidator pattern; requires
          field injection workaround.
  Fix:    Extract to:
            application/user/UpdateUserConstraint.java  (public @interface)
            application/user/UpdateUserValidator.java   (public class, constructor injection)
  Effort: S

P2-4 | Anonymous HashMap used as response body              [plan.txt M1]
  Files:  ArticlesApi.java, UsersApi.java, ArticleApi.java, CommentsApi.java, etc.
  Issue:  Double-brace init (new HashMap<>() {{ put(...); }}) creates anonymous
          subclasses. Pattern is fragile, leaks outer class references, and
          obscures the response contract.
  Fix:    Create typed response record/DTO classes (e.g., UserResponse, ArticleResponse).
          Or use Map.of(...) for immutable single-use wrappers.
  Effort: M

P2-5 | Optional misuse — null check defeats Optional's purpose  [plan.txt M4]
  Files:  ArticleQueryService.java:30-52, CommentQueryService.java:23-35
  Issue:  Pattern: if (x == null) return Optional.empty(); else return Optional.of(x);
          This is manual Optional construction. Use Optional.ofNullable(x) instead.
  Fix:    return Optional.ofNullable(articleReadService.findById(id));
          then chain .map() for conditional enrichment instead of if/else.
  Effort: XS

P2-6 | @Component used where @Service or @Repository is correct  [plan.txt M6]
  Files:  ProfileQueryService.java:12, MyBatisCommentRepository.java:10
  Issue:  @Service enables transaction proxy; @Repository enables exception
          translation. @Component provides neither. Using the wrong stereotype
          silently loses these guarantees.
  Fix:    ProfileQueryService → @Service
          MyBatisCommentRepository → @Repository
  Effort: XS

P2-7 | Exception classes carry no detail message            [plan.txt M5]
  Files:  ResourceNotFoundException.java, NoAuthorizationException.java
  Issue:  Thrown with no context; stack traces and logs contain no information
          about which resource was not found or what was unauthorized.
  Fix:    Add String message constructors:
            new ResourceNotFoundException("Article not found: " + slug)
  Effort: XS

P3-1 | Joda-Time instead of java.time                      [both plans]
  Files:  ArticleQueryService.java, CursorPageParameter.java,
          DateTimeCursor.java, DateTimeHandler.java (MyBatis type handler)
  Issue:  org.joda.time.DateTime superseded by java.time (JSR-310) since Java 8.
          Dead dependency; complicates Jackson and MyBatis configuration.
  Fix:    Replace DateTime with java.time.Instant (DB timestamps) or LocalDateTime.
          Update MyBatis DateTimeHandler. Remove joda-time from build.gradle.
  Effort: M

  File:   build.gradle:2
  Issue:  Multiple CVEs fixed in later releases; Spring Boot 3.x is the current
          stable line. Upgrade requires Java 17+, javax → jakarta namespace migration,
          and the SecurityFilterChain migration (P2-1).
  Fix:    1. First complete P2-1 (SecurityFilterChain) on current version.
          2. Raise Java source/target to 17 in build.gradle.
          3. Upgrade Spring Boot to 3.x.
          4. Run spotless + full test suite; fix javax → jakarta imports.
  Effort: L (do last, after other P2/P3 items)
