#1 Plaintext password stored on user update
  File:   src/main/java/io/spring/application/user/UserService.java:50
          src/main/java/io/spring/core/user/User.java:39
  Issue:  updateUser() passes raw UpdateUserParam.getPassword() to User.update(),
          which sets this.password = password with no encoding. A user who updates
          their password via PUT /user gets a plaintext password written to the DB.
  Fix:    In UserService.updateUser(), encode the password before calling user.update():
            if (!Util.isEmpty(updateUserParam.getPassword())) {
                user.update(..., passwordEncoder.encode(updateUserParam.getPassword()), ...);
            }
  Effort: XS | Impact: CRITICAL — data breach

#2 JWT secret in version-controlled properties
  File:   src/main/resources/application.properties (jwt.secret)
  Issue:  Signing key is committed to source control. Anyone with repo access
          can forge tokens for any user ID.
  Fix:    Remove jwt.secret from application.properties.
          Read from environment variable: @Value("${JWT_SECRET}")
          Set JWT_SECRET in the runtime environment / secrets manager.
  Effort: XS | Impact: CRITICAL — token forgery

#3 GraphQL endpoint fully unauthenticated
  File:   src/main/java/io/spring/api/security/WebSecurityConfig.java:56-57
  Issue:  .antMatchers("/graphql").permitAll() opens all GraphQL mutations
          (create article, update user, follow) to unauthenticated callers.
          REST auth rules are completely bypassed via the GraphQL API.
  Fix:    Remove permitAll() for /graphql. Add authentication checks inside
          each DGS datafetcher/mutation that requires a logged-in user, or
          use a Spring Security expression on the /graphql path with
          per-operation instrumentation.
  Effort: S | Impact: CRITICAL — auth bypass

#4 favoritesCount can be null instead of 0
  File:   src/main/java/io/spring/application/ArticleQueryService.java:156-158
  Issue:  countMap.get(articleData.getId()) returns null for articles with no
          favorites. setFavoritesCount(null) serializes as JSON null instead
          of 0, violating the Realworld API spec.
  Fix:    countMap.getOrDefault(articleData.getId(), 0)
  Effort: XS | Impact: HIGH — incorrect API responses

#5 TOCTOU race condition in MyBatisUserRepository.save()
  File:   src/main/java/io/spring/infrastructure/repository/MyBatisUserRepository.java:22-26
  Issue:  findById() check followed by insert/update is a check-then-act race
          and adds an extra query on every save.
  Fix:    Add a userMapper.upsert(user) backed by SQLite's
          INSERT OR REPLACE INTO users (or ON CONFLICT DO UPDATE).
          Remove the findById pre-check.
  Effort: S | Impact: HIGH — data corruption under concurrency

#6 Article slug regenerated silently on title update
  File:   src/main/java/io/spring/core/article/Article.java (update method)
  Issue:  Updating an article title changes the slug, breaking existing URLs,
          bookmarks, and external links. The duplicate-slug validator only
          runs on creation, so a title change to a previously-used title can
          also produce a duplicate slug.
  Fix:    Freeze the slug at creation time (Realworld spec intent):
          remove slug update from Article.update(). If title changes are needed
          without slug changes, accept title separately from slug.
  Effort: S | Impact: HIGH — URL stability

#7 Validator annotation and class defined inside UserService.java
  File:   src/main/java/io/spring/application/user/UserService.java:59-106
  Issue:  @interface UpdateUserConstraint and class UpdateUserValidator are
          package-private and co-located with the service. This is inconsistent
          with the pattern used by DuplicatedEmailValidator etc. and requires
          @SuppressWarnings for autowiring.
  Fix:    Move to separate files:
            application/user/UpdateUserConstraint.java
            application/user/UpdateUserValidator.java
          Make both public. Use constructor injection in the validator.
  Effort: S | Impact: MEDIUM — maintainability

#8 JwtTokenFilter uses field @Autowired on a non-component class
  File:   src/main/java/io/spring/api/security/JwtTokenFilter.java:18-22
  Issue:  Class suppresses SpringJavaAutowiringInspection. Field injection on a
          manually-constructed object is fragile. Works today only because the
          @Bean factory in WebSecurityConfig triggers Spring's post-processing.
  Fix:    Add constructor: JwtTokenFilter(JwtService, UserRepository).
          In WebSecurityConfig.jwtTokenFilter(), pass both as arguments.
          Remove @Autowired fields and @SuppressWarnings.
  Effort: XS | Impact: MEDIUM — fragile wiring

#9 WebSecurityConfig extends deprecated WebSecurityConfigurerAdapter
  File:   src/main/java/io/spring/api/security/WebSecurityConfig.java:24
  Issue:  Deprecated in Spring Security 5.7, removed in Spring Security 6.
          Upgrading to Spring Boot 3 will break the app.
  Fix:    Replace with SecurityFilterChain @Bean pattern:
            @Bean
            public SecurityFilterChain filterChain(HttpSecurity http) throws Exception { ... }
          Remove the extends clause. Register JwtTokenFilter via
          http.addFilterBefore(...) inside the bean method.
  Effort: M | Impact: MEDIUM — Spring Boot 3 readiness

#10 Joda-Time used throughout instead of java.time
  Files:  ArticleQueryService.java, CursorPageParameter.java,
          DateTimeCursor.java, DateTimeHandler.java (MyBatis type handler)
  Issue:  org.joda.time.DateTime is a legacy library superseded by java.time
          (JSR-310) since Java 8. Adds a build dependency for no benefit.
  Fix:    Replace DateTime with java.time.Instant or LocalDateTime.
          Update MyBatis DateTimeHandler to use java.time types.
          Remove joda-time from build.gradle dependencies.
  Effort: M | Impact: MEDIUM — dependency reduction, future-proofing

#11 Unused spring-boot-starter-hateoas dependency
  File:   build.gradle:37
  Issue:  No HAL links, RepresentationModel, or @EnableHypermediaSupport
          anywhere in the codebase. The dependency adds Jackson auto-config
          that can silently interfere with ObjectMapper customization.
  Fix:    Remove the line from build.gradle.
  Effort: XS | Impact: LOW-MEDIUM — simplification
